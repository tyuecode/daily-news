# 每日国际大事 · 中文播报站

> 每天更新一个**在中国大陆无需翻墙就能打开**的中文渠道，看清国内外热点，也看到国际上不同的观点。

站点是纯静态页面，托管在 **Cloudflare Pages + 自有自定义域名**（不用 GitHub Pages——`*.github.io` 在国内访问很不稳定）。
每天北京时间 8:00 由 GitHub Actions 自动跑完整条流水线，也可以随时手动触发。

---

## 它每天做什么

```
UTC 0:00（北京 8:00）自动触发
  │
  ├─ L0  读历史数据、清掉今日临时产物
  ├─ L1  并发抓取 7 个国际英文源 + 若干中文国内源（单源超时 20 秒）
  ├─ L2  近 36 小时过滤 / URL 去重 / 软新闻剔除 / 图片分辨率归一
  ├─ L3  英文标题分批翻译成中文（每批 8 条）→ bigram Jaccard 聚类 → AI 生成今日大事
  ├─ L4  校验闸门：国家实体对账（防编造）、链接归属（防错位），不合格打回重做 ≤2 次
  ├─ L5  选 6 篇抓正文，按句子边界分段（约 900 字符）全文翻译
  ├─ L6  AI 改写 600 字播报稿 → edge-tts 合成 mp3
  ├─ L7  发布闸门：条数 / 链接 / 中文占比 / 音频文件头，任一不通过就不写任何文件
  └─ L8  写数据、渲染首页与归档、清理 30 天前、提交、部署 Cloudflare Pages
```

**抓不到新闻就不写文件。** 若有效新闻为 0 条，或发布闸门不通过，脚本直接正常退出，
站点保留上一版页面，绝不会被覆盖成空白页。

---

## 页面怎么设计的（易用性优先）

用户的核心诉求是「30 秒内知道今天发生了什么」，「看不同观点」是深入需求。所以：

- **默认视图极其简洁**：每条大事只有「一句话概括 + 一句重要性 + N 家媒体报道」。
- **不同观点默认折叠**：点「查看各家报道 ▸」才展开同一事件的多家媒体报道，
  并提示「以下报道来自 N 家媒体，观点可能不同，请自行判断」。
- **两个版块**：「国内热点」「国际热点」各自成一条时间线，按来源家数优先、时间倒序排列。
- **顶部可听**：有 mp3 给播放器；mp3 合成失败则降级成「朗读播报」按钮（浏览器 SpeechSynthesis）。
- **手机优先**：卡片大、字大、按钮大（最小点击区 44–48px），触摸友好。

## 文件结构

```
.github/workflows/daily.yml   定时 + 手动 + 仓库名守卫 + smoke + 生成 + 提交 + 部署（单文件闭环）
scripts/generate.py           核心脚本：L0–L8，支持 --dry-run
scripts/ai_client.py          Workers AI 调用封装：两种返回结构兼容、指数退避、代码块清洗
scripts/live_check.py         真实抓取联调检查（真实 RSS + 假 AI，零额度，不写站点文件）
smoke_test.py                 运行时冒烟测试（workflow 里先跑，失败即中止）
index.html                    首页（今日完整详情 + 最近 7 天摘要）
archive/YYYY-MM-DD.html       每日归档，保留 30 天
data/entries.json             结构化历史数据（唯一真相源），保留 30 天
data/runs/YYYY-MM-DD.json     运行报告（源状态、AI 消耗估算、闸门结果）
audio/daily.mp3               播报音频，每天覆盖，只留最新一天
requirements.txt              依赖（范围约束，不用精确版本号）
```

## 技术选型

| 环节 | 方案 |
| --- | --- |
| 文本生成与翻译 | Cloudflare Workers AI `@cf/google/gemma-4-26b-a4b-it`（免费层 10000 Neurons/天，本方案日耗约 12%） |
| 语音合成 | **edge-tts**，音色 `zh-CN-XiaoxiaoNeural`（纯免费、无需密钥） |
| RSS 解析 | feedparser |
| 正文提取 | beautifulsoup4 |
| 运行环境 | GitHub Actions，Python 3.11 |
| 托管 | **Cloudflare Pages + 自有域名** |

**国际新闻源（7 个，均为实测可用）**：BBC World、The Guardian、Al Jazeera、France 24、
NPR World、Sky News、Google News (WORLD)。
其中半岛电视台刻意保留——它提供与非西方媒体不同的视角，正是「看不同观点」的关键来源。

**国内中文源（实测结论）**：**中新网**官方 RSS 的 4 个频道（即时/要闻/时政/社会），
每源 30 条、境外访问畅通、时间字段完整；**联合早报**走第三方公益镜像（有真实配图）；
另外补充了 **纽约时报中文网**和**法广 RFI 中文**两个海外中文媒体。

⚠️ 国内版块曾经只有一个信源。线上体检发现：8 条事件**全部来自中新网**，多源簇为 0——
「看到不同观点」这个核心目标在国内版块完全没实现。补了上面两个海外中文源之后，
国内版块能有 4 家媒体的观点对比。

⚠️ 以下源**实测不可用，已从配置中剔除**，不要再用：
- **联合早报官方 RSS** 已下线（返回 SPA 网页 / 404）
- **人民网、新华网、新浪 RSS 全部停更**（最新条目停在 2016–2025 年）。
  它们形式上是合法 RSS、`bozo=False`、条目上百条，是最危险的「僵尸源」——
  脚本内置了**停更源守卫**，最新条目超过 7 天的源会整源丢弃并记入运行报告
- **央视 RSS** 全部 404；**rsshub.app** 公共实例已被 Cloudflare 拦截（403）
- **BBC 中文**：境外可访问、42 条、有配图，但实测返回的是 **100% 繁体**内容
  （「特朗普訪華之際 美國封堵中國公司」）。本站面向简体读者，故不采用
- **德国之声中文**：可用、简体、当天，但 **0/15 没有任何配图**，
  卡片会变成纯文字与其他版块割裂，暂不加入（配置里留了注释行）
- **端传媒**：美国出口实测也连不上（`RemoteDisconnected`），暂不加入
- **界面新闻**：可用但是**财经媒体**（公司公告/IPO/股价为主），
  放进「国内热点」会严重稀释时政社会新闻，且 RSS 无任何图片字段
- **关键评论网**：`/feed` 返回 404

**成本：全程零成本**，不需要绑定信用卡，也不需要实名认证。

### 为什么用 edge-tts 而不是 Workers AI 的 TTS

Workers AI 的 `@cf/myshell-ai/melotts` 已于 **2026-11-20 弃用**，同厂的 `aura-1` 又只支持英语，
无法满足中文播报。改用 **edge-tts**（微软开源项目）：完全免费、不需要 API key，
中文音色 `zh-CN-XiaoxiaoNeural` 自然度足够，几秒就能合成 600 字播报稿，
也不占用 Workers AI 的免费额度。

⚠️ **edge-tts 必须用 7.x，不能用 6.1.x**（这是实测踩出来的坑）：
6.1.19 内置的 Chromium 130 / `Sec-MS-GEC` token 已过期，websocket 握手会被微软返回
`403 WSServerHandshakeError`，三次重试全挂、当天没有音频。7.x 修复了握手。
因此 `requirements.txt` 里写的是 `edge-tts>=7.0`（**刻意不设上界**——微软一旦再次收紧
token，通常只有最新版跟得上，被上界锁死在旧版会突然全线失败）。

另外，edge-tts 的失败是**服务端随机抖动**，与文本长度无关：同一段文字可能连续
5 次全失败，也可能连续成功。所以脚本用 **8 次重试 + 线性退避**（实测可稳定到 5/5，
平均约 2 次成功一次），失败才降级为浏览器朗读。

## 你需要手动完成的设置

### 1. 添加三个 Repository secrets

打开仓库 **Settings → Secrets and variables → Actions → New repository secret**，添加：

| 名称 | 内容 |
| --- | --- |
| `CF_ACCOUNT_ID` | 你的 Cloudflare 账号 ID |
| `CF_API_TOKEN` | Cloudflare API Token，需同时具备 **Workers AI:Edit** 和 **Pages:Edit** 权限 |
| `CF_PAGES_PROJECT` | Cloudflare Pages 项目名（例如 `daily-news`） |

这三个值**只从 GitHub Secrets 读取，不写进代码、不进仓库、不进日志**。

（可选）在 **Settings → Secrets and variables → Actions → Variables** 里加一个
`SITE_URL`，例如 `https://news.你的域名.com`，用于页面里的 canonical 链接。

### 2. 首次创建 Cloudflare Pages 项目并绑定自定义域名

在 Cloudflare 后台 **Workers & Pages → Create → Pages** 创建一个项目，
项目名与 `CF_PAGES_PROJECT` 保持一致；然后在项目设置里 **Custom domains** 绑定你的域名，
按提示添加 CNAME 记录（域名已托管在你的 Cloudflare 账号时通常一键完成）。

首次执行 workflow 时 wrangler 也会尝试自动创建项目，但绑定域名仍需在后台点一次。

### 3. 手动跑一次验证

到仓库 **Actions → 每日新闻自动更新 → Run workflow** 跑一次，
确认 Secrets 生效、页面能正常生成、自定义域名能打开。

### 4. 之后就是自动的

以后每天北京时间 8:00 自动更新。GitHub 定时任务在高峰时段可能延迟 5–45 分钟，属正常现象。

### 5. 中文国内源若不可用，改配置即可

国内源写在 `scripts/generate.py` 的 `DOMESTIC_FEEDS` 列表里，改这个列表就能增删，
不用动任何逻辑。若全部中文源都抓不到，国内版块会自动退化为「从国际源里筛选涉华报道」，
并在页面上明确注明，不会留空。

## 本地 dry-run（不花钱、不联网、不消耗额度）

`--dry-run` **零网络、零 Cloudflare 调用、零额度消耗**。
输出全部写到独立的 `_dryrun/` 目录，**不会覆盖真实的** `index.html`、`data/`、`audio/`。

```bash
python -m pip install -r requirements.txt
python smoke_test.py                      # 运行时冒烟测试，先跑这个
python scripts/generate.py --dry-run      # 端到端演练（默认走无音频降级分支）
python scripts/generate.py --dry-run --dry-run-tts-ok   # 额外验证「有音频」渲染分支
python scripts/live_check.py              # 真实抓 RSS 联调（假 AI，零额度，不写站点文件）
```

dry-run 覆盖的场景：多源簇、Google News 条目、软新闻、无图条目、
TTS 失败降级、国内/国际双版块，以及「31 天前的数据与归档被自动清理」。

## 架构要点（为什么这么做）

- **生成与部署在同一个 workflow 文件里。** 因为 `GITHUB_TOKEN` 推送的提交不会触发另一个工作流，
  拆成两个文件会导致「提交了但页面不更新」。
- **仓库名守卫。** workflow 第一步校验 `GITHUB_REPOSITORY` 必须等于 `tyuecode/daily-news`，
  防止误操作其他仓库（尤其是用户的主页仓库）。
- **运行时冒烟测试而非只做语法检查。** `py_compile` 只查语法不查 `NameError`，
  历史上就出现过语法通过、线上却因函数未定义导致整站空白的事故。
- **用稳定 `cid` 而不是数组下标。** 摘要与链接靠 `cid` 绑定，
  某条事件被打回重做时不会影响其它条目，也不会张冠李戴。
- **翻译防编造。** 摘要生成后抽取国家实体，与所链接原文标题比对；
  有 2 个以上国家在原文里找不到，就判定为编造，打回重做或丢弃该条。
- **每轮开始先把旧 `daily.mp3` 挪走。** 避免某天 TTS 失败时，页面播着昨天的音频配今天的稿。
  此时页面自动降级为浏览器 `SpeechSynthesis` 朗读。
- **音频文件必须按文件头校验。** 用文件大小猜会把几 MB 的 JSON 当音频写进文件，
  页面放出来是乱码。合法头为 `ID3` 或 `0xFF` 帧同步。
- **所有外部文本写入 HTML 前都做 `html.escape()`。** RSS 里的恶意标题不能破坏整页结构。

## 关键参数（都在 `scripts/generate.py` 顶部）

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `WINDOW_HOURS` | 36 | 新闻时效窗口 |
| `KEEP_DAYS` | 30 | 归档保留天数（音频只留最新一天） |
| `TRANSLATE_BATCH` | 8 | 每批翻译条数（一次给 20 条模型只会翻前 5 条） |
| `CLUSTER_THRESHOLD` | 0.25 | 中文 bigram Jaccard 聚类阈值（见下方说明） |
| `SOURCE_TIMEOUT` | 20 | 单源抓取超时（秒） |
| `TTS_VOICE` | `zh-CN-XiaoxiaoNeural` | 播报音色 |
| `TTS_ATTEMPTS` | 8 | 语音合成重试次数（服务端随机抖动，必须给足） |
| `MAX_EVENTS_PER_SECTION` | 8 | 每版块最多保留几条大事 |
| `PUBLISHER_SEAT_QUOTA` | 2 | 单个媒体最多占几个单源席位（防垄断） |
| `THEME_PREFIX_MIN` | 5 | 同主题判定的公共前缀长度（见「同主题归并」） |
| `THEME_MIN_EVENTS` | 2 | 至少几条才归成一个主题组 |
| `BROADCAST_CHAR_LIMIT` | 900 | 播报稿字数上限（提示词与截断共用） |

### 关于「媒体席位配额」

**设计原则：热点覆盖优先，多样性是福利不是硬指标。**

项目初衷是「快速了解新闻热点，看不同观点是深入需求而非默认需求」。
所以席位**永远优先填满**——读者打开页面是为了知道今天发生了什么，
不是来检查媒体清单的。

配额（`PUBLISHER_SEAT_QUOTA = 2`）只解决一件事：防止某一家媒体凭发稿量大
霸占整个版块。历史上出现过国际版块 8 条里 France 24 独占 5 条。

具体行为（`apply_publisher_quota`）：
1. 按（来源家数 → 时间）排序，依次入选，每个媒体最多 2 席
2. 席位没满 → 先补未达配额的其他媒体
3. 还不够 → 允许超配额补满（宁可重复来源，也不浪费席位）

⚠️ 这里踩过两次坑，都是「把多样性当成硬指标」：
- 第一次：完全按排序取，France 24 垄断 5 席
- 第二次：加了「每个媒体保底 1 席」，结果**国际版块 179 条素材只显示了 5 条**，
  3 个席位被浪费，还挤掉了更重要的热点——与「了解热点」的初衷直接冲突

现在的实现兼顾两者：素材充足时配额严格生效（多样性有保障）；
素材紧张时优先填满席位（热点不丢失）。

### 关于「国内版块混进国外新闻」（源级分类）

线上反复出现过这样的国内版块：

```
[c2]  韩国高考防作弊措施升级，李在明称作弊是严重犯罪
[c3]  日本"隼鸟2"号小行星探测器因发动机故障变更探测目标
[c7]  乌克兰再次袭击克里米亚大桥
[c17] 美国两部门声明对Megaspeed展开调查
```

**根因**：中新网的「即时」「要闻」「社会」频道**不是纯国内新闻**，它把国际稿混在里面。
实测 106 条中新网条目里有 38 条完全不涉华。

早期方案是维护一份「海外媒体白名单」再做内容判定，但**中新网不在白名单里**，
它的条目根本没被检查过。名单式方案的必然缺陷就是漏一个源就泄漏。

现在的解法是**源级分类声明**：每个源在配置里声明 `scope`，`smoke_test` 会强制检查：

| scope | 含义 | 例子 |
| --- | --- | --- |
| `intl` | 整源都是国际新闻 | BBC、The Guardian、Al Jazeera |
| `domestic` | 整源都是国内新闻 | （当前没有纯国内源） |
| `mixed` | 综合媒体，需逐条按内容判定 | 中新网各频道、联合早报、纽约时报中文网、法广RFI |

分流在 `assign_sections()` 里完成：`intl` 一律进国际，`domestic` 一律进国内，
`mixed` 逐条判断是否涉华。**不再依赖任何 publisher 白名单。**

判断「是否涉华」用 `is_china_related()`，关键词表覆盖：
国家与部委、领导人姓名、港澳台、主要城市与省份、对华关系简称、
中国主办的国际场合（APEC/G20/进博会）、航天工程（神舟/嫦娥/北斗）、
中国特有文化议题。

⚠️ 两个反直觉的坑（都是实测踩出来的）：
- **「高考」不能当中国特征词**——韩国也有高考，「韩国高考防作弊」因此被误判成中国新闻
- **「全国」过于宽泛**——任何国家的新闻都可能用，会把无关新闻全捞进国内版块

真实数据实测准确率：106 条里 103 条正确（97%），
仅剩 2 条不重要的中国软新闻（如「AI漫剧看多了觉得真人变丑」）被判为国外。

### 关于「同主题归并」

线上出现过这样的情况：某天国内版块 8 条里 **4 条都是「习近平会见X国领导人」**
（会见的对象分别是越南、加拿大、巴新、墨西哥）。读者打开页面会觉得
「今天只有一件事」。

**但这不是「同一事件的多家报道」，不能按 cluster 那样合并**——会见的对象不同，
合并会丢失信息。所以做了两级结构：

```
theme（同系列事件） → event（单条事件） → cluster（同一事件的多家报道）
```

页面表现：主卡片显示一句共同概括（如「习近平在APEC期间会见四国领导人」），
点开后才列出 4 条各自的动态。实测效果：该版块 8 张卡片 → 5 张，**事件一条没丢**。

识别方式用「**标题公共前缀**」而不是相似度：
实测这 4 条两两 bigram 相似度只有 0.17–0.23（因为国家名完全不同），
任何合理阈值都抓不到；但它们的公共前缀恰好都是「习近平会见」（5 字）。
前缀规则可预测、可解释，不会把无关新闻误合并。

相关常量：`THEME_PREFIX_MIN = 5`（公共前缀至少 5 字）、
`THEME_MIN_EVENTS = 2`（至少 2 条才成组）。

⚠️ 有个必须注意的耦合：**同主题的多条事件要共享一个配额席位**。
因为配额按 publisher 限 2 席，而 4 条会见往往都来自中新网——
如果不共享席位，配额会把主题组砍成 2 条，归并就残缺了。

### 关于国内版块的配图

中文源（中新网）的 RSS **完全不带图**，导致国内版块曾经 0/8 有图，
而国际版块 7/8 有图，滚动起来观感割裂。

现在补图走两步：
1. `entry_image()` 从 RSS 的各种字段里提取，并用 `looks_like_article_image()` 过滤掉
   站点 logo、导航箭头、广告图、二维码、通用 `social-share.png` 等非文章图
2. `backfill_images()` 对入选但无图的事件，打开正文页取 `og:image`

⚠️ 一个重要的实现约束：**只信任站点自己声明的 `og:image` / `twitter:image`，
不做「正文第一张 `<img>`」兜底**。实测中新网正文页没有 `og:image`，
页面上全是导航箭头和广告图，任何兜底都会取到错图（试过取到 `toparr.png` 导航箭头）。
**取到错图比没有图糟糕得多**——读者看到头条大图是个箭头，会认为站点坏了。
所以中新网的新闻会渲染成纯文字卡片，这是刻意的降级；联合早报（有真实配图）则正常显示。

### 关于聚类阈值 0.25

初版按经验设成 0.35，但用真实抓取数据做阈值扫描后发现它**太保守**：
6 组「明显是同一事件、不同媒体不同措辞」的标题对里，只有 1 组能达到 0.35，
导致 11 条国际大事中只有 1 条是多源簇——「看不同观点」这个核心目标基本落空。

改到 **0.25** 后，同事件合并数提升到 3/6，而不同事件的误并仍然是 **0/6**。

降低阈值必须配套一个守卫：`entity_conflict()`。
因为存在这样的陷阱——「习近平会见加拿大总理卡尼」和「习近平会见巴布亚新几内亚总理马拉佩」
字面框架高度雷同（相似度 0.23），却是完全不同的两件事。
该守卫会在「两边都提到国家、且没有任何共同国家」时禁止合并。

## 已知故障与处理（真实遇到过）

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| Actions 标红，报 `Authentication error [code: 10000]` | `CF_API_TOKEN` 缺 **Pages:Edit** 权限（只有 Workers AI 权限时生成能成功，部署会失败） | 到 API Tokens 页面补上 Pages:Edit，重跑 workflow |
| 页面没有音频，只有「朗读播报」按钮 | ① `edge-tts` 被锁在 6.1.x（403 握手失败）② 服务端随机抖动用完重试 | 确认 `requirements.txt` 是 `edge-tts>=7.0`；抖动由 8 次重试兜住 |
| 某天页面没更新 | 发布闸门不通过（条数不足/中文占比过低） | 看 `data/runs/<日期>.json`，这是刻意设计，保留上一版而不是发空白页 |
| 国内版块为空 | 中文源全部不可用 | 会自动退化为「从国际源筛选涉华报道」并在页面注明；按运行报告调整 `DOMESTIC_FEEDS` |
| 国内版块全是「中新网」一家 | 中文源里只有中新网可用，联合早报常超时 | 配额只能防垄断，不能凭空造多样性——需要补真正不同的中文媒体源 |
| 国际新闻出现在「国内热点」里 | `中新网·国际`（world.xml）曾被当成国内源 | 已移除；中文国际新闻应归到国际版块 |
| 国内卡片没有配图 | 中新网 RSS 不带图，且正文页无 `og:image` | 刻意降级为纯文字卡片；取错图（导航箭头）比没图更糟 |
| 出现几年前的旧新闻 | 撞上「僵尸源」（HTTP 200 但停更） | 已内置停更源守卫（最新条目超 7 天整源丢弃），新加源也受保护 |

## 常见问题

**Q：页面打开了但没有音频？**
先看播报区是不是「朗读播报」按钮——那是 TTS 失败后的正常降级，点一下用浏览器朗读即可。
原因可在 `data/runs/<日期>.json` 里查。

**Q：某天页面没更新？**
看 Actions 的运行日志和 `data/runs/<日期>.json`。若是发布闸门不通过（条数不足、中文占比过低），
说明当天抓取质量确实不行，站点保留上一版是刻意设计，不是故障。

**Q：想加新闻源？**
英文源加到 `INTL_FEEDS`，中文源加到 `DOMESTIC_FEEDS`，都是配置项，改完不用动逻辑。
加源后建议本地跑一次 `python scripts/generate.py --dry-run` 确认没有意外。

**Q：Workers AI 额度会不会不够？**
完整一轮约消耗 1,170 neurons，占免费层每日 10,000 的约 12%，且运行报告里会记录实际估算值。
